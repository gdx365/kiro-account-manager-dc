## 1. 关键问题摘要

### P0（必须先处理）

1. 全仓存在明显乱码（Mojibake）
- 现象：大量注释、中文文案、description 字段出现 `鏍稿績妯″潡` / `鍛戒护` 等乱码。
- 已确认文件（示例）：
  - `src-tauri/src/main.rs`
  - `src/routes.tsx`
  - `src/main.tsx`
  - `src/utils/cn.ts`
  - `src/components/features/AccountManager/hooks/useSwitchAccount.ts`
  - `package.json`（`description`）
- 风险：可读性差、字符串错误、潜在语法损坏、后续合并冲突难定位。

2. 前后端接口不一致（CLI 切号链路）
- 前端调用：`useSwitchAccount.ts` 调用了 `invoke('build_cli_switch_payload', { account })`。
- 后端现状：`build_switch_payload` 仅是 `kiro_cli_cmd.rs` 内部函数，不是 `#[tauri::command]`，也未注册到 `generate_handler`。
- 同时，前端调用 `switch_to_cli_account` 传 `{ payload }`，而后端函数签名是 `(account_id, db_path, state)`。
- 风险：CLI 切号路径运行时必然失败或行为异常。

3. 基础构建链路当前不完整
- `npm run build` 失败：本地未安装前端依赖（`vite` not recognized）。
- `cargo check` 失败：`tauri::generate_context!()` 依赖 `../dist`，当前路径不存在。
- 风险：无法稳定做回归验证，整改过程容易引入新问题。

### P1（高优先级）

4. 命令层存在“功能残留/未接线”风险
- 前端 `invoke` 实际使用命令显著少于后端已注册命令数量。
- 可能属于“预留能力”，但当前状态无法区分“预留”与“历史残留”。
- 风险：维护成本高、权限面扩大、文档与实际不一致。

5. 工具函数重复实现
- `src/lib/utils.ts` 与 `src/utils/cn.ts` 都实现了 `cn(...)`，但逻辑不同（一个含 `twMerge`，一个仅 `clsx`）。
- 风险：样式合并行为不一致，造成 UI 隐性 bug。

### P2（中优先级）

6. 注释/文案与代码语义偏移
- 乱码导致注释不可用；部分注释可能已失真，不再描述真实行为。
- 风险：后续重构误判。

## 2. 分阶段整改方案

## 阶段 A：编码与文本修复（P0）

目标：统一编码、消除乱码、确保文件可读可维护。

执行项：
1. 统一文本编码为 UTF-8（无 BOM），统一行尾（建议 LF，按 `.editorconfig`）。
2. 扫描并修复所有乱码字符与受损字符串（注释、错误信息、UI 文案、JSON 文本）。
3. 重点先修文件：
   - `src-tauri/src/main.rs`
   - `src/components/features/AccountManager/hooks/useSwitchAccount.ts`
   - `package.json`
   - `src/routes.tsx`
   - `src/main.tsx`
   - `src/utils/cn.ts`
4. 增加编码守护：新增脚本检查非法替换字符/常见 mojibake 特征。

验收标准：
- `rg -n "鏉|鍛|�" src src-tauri package.json` 无命中（允许白名单例外）。
- 中文文案可正常阅读，JSON 与 TS/Rust 可正常解析。

## 阶段 B：前后端命令契约对齐（P0）

目标：修复调用链断裂，建立可持续契约检查。

执行项：
1. 修复 CLI 切号接口（二选一，建议方案 1）：
   1. 前端改为传 `accountId + dbPath`，直接调用现有 `switch_to_cli_account`。
   2. 或后端新增 `build_cli_switch_payload` tauri 命令并保持前端现有调用方式。
2. 为 `invoke` 命令名建立单一来源（常量或类型定义），避免字符串散落。
3. 增加契约检查脚本：
   - 提取前端 `invoke('...')` 列表；
   - 对比后端 `#[tauri::command]` 与 `generate_handler` 注册；
   - CI 失败条件：前端调用未注册命令。

验收标准：
- CLI 切号链路端到端可运行（IDE/CLI 两路径）。
- 不存在“前端调用但后端未注册”的命令。

## 阶段 C：残留能力清点与裁剪（P1）

目标：消除历史残留，降低维护面。

执行项：
1. 输出三张清单：
   - 前端在用命令；
   - 后端已注册命令；
   - 后端实现但未注册命令。
2. 对“后端已注册但前端未使用”逐项标记：
   - `active`（计划保留）；
   - `internal`（仅内部/未来用）；
   - `deprecated`（待删除）。
3. 对 `deprecated` 命令执行两步移除：
   - 先从前端入口和文档移除；
   - 下一版本再移除后端实现与注册。
4. 同步更新 `README`/`docs` 的功能说明。

验收标准：
- 每个命令都具备状态标签和归属说明。
- 无“无人负责的已注册能力”。

## 阶段 D：重复代码合并与规范化（P1）

目标：减少分叉实现，统一行为。

执行项：
1. 合并 `cn` 工具函数：仅保留一个实现（建议保留 `twMerge + clsx` 版本）。
2. 全量替换引用并删除重复文件。
3. 建立 `utils`/`lib` 分层约定，避免同名工具多处定义。

验收标准：
- `cn` 仅有一个导出来源。
- 样式冲突类名合并逻辑一致。

## 阶段 E：构建与回归基线（P0/P1 贯穿）

目标：每次整改可验证、可回滚。

执行项：
1. 固化最小回归命令：
   - `npm install`
   - `npm run build`
   - `cargo test`（`src-tauri/`）
2. 为 Tauri `frontendDist` 缺失场景提供开发说明（先 build 前端或使用 dev server）。
3. 增加 PR 模板项：
   - 命令契约检查结果
   - 编码检查结果
   - 关键页面手工验证（亮/暗主题、Select hover/selected、placeholder 可读性）

验收标准：
- 新 PR 至少通过前端 build + 后端 test。
- 问题可复现、可验证、可回滚。
